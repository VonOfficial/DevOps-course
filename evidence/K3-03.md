# K3-03. Тестовый барьер

В Student CI добавлен отдельный шаг запуска тестов:

`python -m unittest discover -s tests -p test_app.py -v`

Тест `test_create_request` проверяет, что создание заявки возвращает HTTP-статус 201 и запись сохраняется.

## Неуспешный запуск

В тесте временно изменил ожидаемый статус с 201 на 200.

- [Неуспешный запуск Student CI](https://github.com/VonOfficial/DevOps-course/actions/runs/43464314989).
- Событие: push.
- SHA: `f926cbd176a9f637c9e12b4e08b6d6826daa82bd`.
- Результат: failure.

Строки лога:

```text
AssertionError: 201 != 200
FAILED (failures=1)
Error: Process completed with exit code 1.
```

Приложение вернуло 201, но тест ожидал 200. Проверка завершилась с ошибкой, поэтому CI стал красным. Причина — намеренно неверное ожидание в тесте.

## Исправление

Вернул ожидаемый статус 201 и сохранил изменение новым коммитом с сообщением «201».

- [Исправленный запуск Student CI](https://github.com/VonOfficial/DevOps-course/actions/runs/43466045838).
- Событие: push.
- SHA: `e99f7d33f8b4c66395b70ad2a3a5b89d5bb34a3e`.
- Результат: success.
- Все 7 тестов прошли, в логе указан результат `OK`.

В итоговой версии тест снова ожидает 201.

## Вывод

Тестовый барьер работает: несовпадение фактического результата с ожидаемым приводит к ошибке команды и неуспешному запуску CI. Поэтому неверное ожидание теста тоже делает CI красным.
